How It Works

End-to-end research pipeline

Collect clean demonstrations, train a CNN or VLA policy, and deploy back to the robot — all from the same codebase.

01

Connect the Robot

Join the robot hotspot for first-time setup, move both devices onto shared Wi-Fi, then SSH normally for the rest of the project.

02

Record Episodes

Drive the robot with keyboard or PS5 gamepad. Each accepted lap is saved as a timestamped episode with video, parquet actions, and metadata.

03

Auto-Collect with CV

Run the autonomous collector: a PD controller follows the tape line and accepts full laps automatically, scaling up dataset size without manual driving.

04

Train CNN Baseline

Train a configurable 4-block CNN on stacked frames. Supports tape-color filtering, fine-tuning, and color-generalization sweep experiments.

05

Export to LeRobot

One command converts the episode folder to a LeRobot-compatible dataset ready for VLA fine-tuning with OpenVLA, π₀, or similar models.

06

Deploy Policy

Load a trained checkpoint and run closed-loop inference. The laptop streams velocity commands to the robot server over Wi-Fi at 10 Hz.

Configurable depth & width encoder_channels and head_hidden_sizes are first-class config fields — sweep different architectures without code changes.
Backward-compatible checkpoints The loader infers architecture from the state dict, so older checkpoints load correctly even as the config schema evolves.
Color-generalization experiments Train on red tape, fine-tune on white tape with frozen early blocks. The sweep script varies the number of white episodes and reports per-color validation loss.
Colab training A ready-to-run Colab notebook uploads data from Drive, trains on T4 GPU, and saves best checkpoints back to Drive for download.
What's Included

Everything in one repo

No dashboard, no black boxes — just a clean, scriptable stack you can understand and extend.

🤖

Robot Server

Lightweight Flask server exposing camera, velocity, servo, and health endpoints. Runs on the LeRover's Raspberry Pi.

🎮

Teleop Client

Keyboard and PS5 gamepad teleoperation with live camera feed. Gamepad gives analog inputs for smoother demonstrations.

🚗

Autonomous Collector

CV-based PD line follower that drives full laps unattended, with automatic episode acceptance and corner-handling tuning.

🧠

CNN Policy

Train, evaluate, and deploy a CNN policy that maps stacked frames to velocity commands. Fully configurable architecture.

📦

LeRobot Export

One-command conversion to LeRobot v3 format — ready for OpenVLA, π₀, or any HuggingFace-compatible VLA fine-tuning pipeline.

☁️

Hugging Face Upload

Interactive uploader that lists sessions, shows episode counts, and pushes a selected session to a HF dataset repo.

📊

Training Logs

Per-epoch JSON summaries with train/val loss, per-color metrics, and checkpoint history. Easy to plot with the Colab notebook.

🔬

Segmentation Support

Optional video masking pipeline to strip background pixels and train on segmented frames for visual robustness experiments.

Open Problems

Research questions

Seventeen concrete questions grounded in the LeRover's 3-DOF holonomic drive, camera-only observations, and LeRobot-compatible infrastructure.

Action Space & Control
Q1
Body velocity vs. raw wheel duties Does predicting (vx, vy, ω) outperform predicting raw wheel duties? The server supports both endpoints for a direct comparison.
Q2
3-DOF data efficiency Does the holonomic action space require significantly more demonstrations than a 2-DOF differential robot for the same task?
Q3
Strafe for fine corrections Can a VLA learn to exploit strafing for precise lateral adjustments that a non-holonomic robot physically cannot perform?
Data Efficiency
Q4
Minimum demonstrations What is the minimum number of demonstrations for a reliable loop-following policy? Sweep N ∈ {5, 10, 20, 50} with the --episodes flag.
Q5
Gamepad vs. keyboard data quality Do smooth analog gamepad trajectories produce better policies than discrete keyboard inputs?
Language Generalization
Q6
Instruction paraphrase transfer Does a VLA fine-tuned on LeRover data transfer across semantically equivalent instructions without additional data?
Q7
Cross-room transfer with language Does language conditioning improve cross-room generalization compared with image-only conditioning?
Visual Robustness
Q8
Lighting & camera drift How sensitive is the policy to lighting changes and small camera angle drift? The fixed CSI camera enables controlled experiments.
Q9
Landmark dependence Does the policy rely on specific visual landmarks? Occlude them and test whether degradation is graceful or catastrophic.
Foundation Model Fine-Tuning
Q10
Pre-trained VLA data efficiency How many LeRover demonstrations does a pre-trained VLA (OpenVLA, π₀) need before it outperforms a CNN trained from scratch?
Q11
Mecanum action space transfer Does a pre-trained VLA generalize to the novel 3-DOF holonomic output without explicit action-space adaptation?
Temporal Modeling · Dataset Quality · Deployment
Q12
Observation history How many frames of history does the policy need? Compare 1-frame, 3-frame, and 5-frame stacked input at 10 Hz.
Q13
Action conditioning Does adding the previous action as input improve motion smoothness? The shifted_action state source can be ablated at training time.
Q14
Accept/discard discipline Does the episode accept/discard workflow during recording measurably affect final policy performance?
Q15
Direction balance Does recording equal clockwise and counterclockwise loops improve rotation generalization?
Q16
Real-time inference budget What is the maximum model size that sustains 10 Hz inference over Wi-Fi within the round-trip latency budget?
Q17
Quantization on-device Does INT8/FP16 quantization of a fine-tuned VLA preserve task success on the LeRover?
Get Started

Up and running in minutes

The laptop does everything — recording, training, and deployment. The robot only runs a small HTTP server.

Setup
Collect
Train
Deploy
# 1. Clone and install laptop dependencies
git clone https://github.com/MichaelAguadze/leorovervla.git
cd leorovervla
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-laptop.txt

# 2. Deploy server to the robot (SSH must be set up)
bash scripts/deploy_server.sh deps
bash scripts/deploy_server.sh start

# 3. Install CNN training extras
pip install -r requirements-cnn.txt
# Manual teleoperation (keyboard or gamepad)
python -m client.cli --robot-ip <ROBOT_IP>
# choose CNN-based → dataset recording in the launcher

# Autonomous CV collection (hands-free)
python -m client.auto_collect \
  --robot-ip  <ROBOT_IP>  \
  --dataset   leorover_cnn_red \
  --episodes  20  \
  --tape-color red

# Episodes are saved to:
#   data/leorover_cnn_red/episodes/session_YYYYMMDD_*/episode_*/
# Train the CNN baseline (auto-picks MPS on Apple Silicon)
python -m loop_cnn.train \
  --episodes-dir data/leorover_cnn_red/episodes \
  --run-dir      runs/cnn_v1 \
  --num-workers  2

# Evaluate a saved checkpoint
python -m loop_cnn.eval \
  --episodes-dir data/leorover_cnn_red/episodes \
  --checkpoint   runs/cnn_v1/run_<DATE>/checkpoints/best.pt

# Export to LeRobot format for VLA fine-tuning
python scripts/export_lerobot.py \
  --episodes-dir data/leorover_nav/episodes \
  --output-dir   data/leorover_nav/lerobot \
  --repo-id      <HF_USERNAME>/<DATASET_NAME>
# Run the trained CNN policy on the robot
python -m loop_cnn.drive \
  --robot-ip   <ROBOT_IP> \
  --checkpoint runs/cnn_v1/run_<DATE>/checkpoints/best.pt

# Upload a recorded session to Hugging Face
python scripts/upload_hf_session.py
# interactive picker — select session, upload to HF dataset repo
